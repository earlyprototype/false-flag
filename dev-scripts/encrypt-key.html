00SEAL A SHARED KEY

This page takes an OpenRouter API key and a passphrase and returns an encrypted blob. Save the blob as docs/play/shared-key.json, commit it, and testers who know the passphrase can play the browser build against your account without ever holding your key.

This page runs entirely on your machine. Open it from disk with file://. It loads nothing and sends nothing — the Content Security Policy in its <head> forbids every outbound request the browser can make. Your key is typed here, encrypted here, and never leaves this tab. This is the only page in this project where you type the key in the clear — but not the only code that ever holds it in the clear: once a tester unlocks the blob, the play page necessarily keeps the decrypted key in memory for that tab in order to call OpenRouter with it.
Understand what you are publishing. The blob is ciphertext, but it is ciphertext on the public internet, in a public git repository, and git keeps history. Once you commit it, assume it is public forever and that deleting the file later removes nothing. Anyone who has the passphrase — now, or in five years, from anyone you gave it to — can recover the key from it. The only real off-switch is revoking the key at OpenRouter.
Cap the key before you seal it. At openrouter.ai/settings/keys give this key a credit limit, and make it a key you use for nothing else. Everyone who unlocks the page spends from it.

04WHAT THIS ACTUALLY DOES

  • The passphrase is normalised (NFKC) and stretched with PBKDF2-HMAC-SHA256 over a fresh 16-byte random salt, for the iteration count above, into a 256-bit key.
  • That key encrypts the API key with AES-256-GCM under a fresh 12-byte random IV. GCM authenticates as well as encrypts, so a wrong passphrase fails on the authentication tag and yields nothing at all.
  • Salt, IV and ciphertext are published; the passphrase is not. There is no password check, no hint, and no verifier field in the blob — the only signal a wrong passphrase produces is failure.
  • Everything is window.crypto.subtle. No library is loaded and no scheme is invented here.

Attack cost is therefore exactly the cost of guessing the passphrase, times the iteration count. That is why this page refuses weak ones.
