## 1. What the project is

FALSE FLAG is an LLM-driven UK political-military crisis wargame. You are the
Prime Minister in COBRA. There is no menu: you type a paragraph saying what you
are actually doing, and a cabinet of LLM-driven advisors reads it, argues with
it, refuses it, or points out what you forgot. Inspired by Sky News/Tortoise's
*The Wargame* podcast (credits in `docs/INSPIRATION.md`).

**Five front ends over one engine:**

| Surface | Entry point |
|---|---|
| Terminal CLI | `cli/main.py`, `cli/main_dashboard.py` |
| Headless engine | `engine/game_manager.py` |
| HTTP API (FastAPI + SSE) | `api/server.py` |
| Browser (Pyodide) | `docs/` — `index.html`, `app.js`, `worker.js`, `py/bridge.py`, `game.zip` |
| Dev harness | `dev-scripts/play_campaign.py` |

The browser build is the one the owner plays: <https://earlyprototype.github.io/false-flag/>
GitHub Pages serves `docs/` from `main`, so **merging to main is deploying.**
`docs/game.zip` is a vendored bundle of the engine — a parity test fails if you
change bundled code without running `python dev-scripts/build_play_bundle.py`.

## 3. What was actually fixed in this session (and how it was proven)

**a. Batch LLM calls were dead in the browser — the big one.**
Pyodide cannot start threads. Both drivers' `batch_generate_text` used
`ThreadPoolExecutor`, which raised `RuntimeError: can't start new thread` at the
first `submit`. Every multi-advisor call — "ask the whole room", the
around-the-table reactions after a decision — died instantly, silently fell back
to the offline mock cast, and the player-facing notice blamed the network.
Fixed with a sequential fallback in `llm/openai_compat_driver.py` and
`llm/gemini_driver.py`; pinned by `tests/test_batch_threadless.py`.
**Proof:** headless Chromium against the real build with the owner's key —
before, ask-all made 1 outbound call and produced 5 mock answers; after, 5
outbound calls and 5 in-character cabinet answers, no fault notice.

**b. Fault notices lied.** A failed call always said "that is usually the
network". It now names the model id and, for `:free` slugs, says the shared
public allowance is the likely cause (`docs/py/bridge.py: describe_llm_faults`).

**c. Presentation.** Narrative renders as flowing prose (a "flow pen" mode on
`AnsiPen` emits one logical line per paragraph; the page soft-wraps it), and the
reading face is applied page-wide, while chrome — strips, rules, labels,
controls, metrics, the terminal pane — stays monospace. Merged in #55.

**d. Cache mismatch (PR #58, unmerged).** #55 changed the transcript pane from
`<pre class="screen">` to `<div class="screen">`. Browsers holding the old
`play.css` applied its `pre.screen` rules to markup that no longer matched:
no `white-space: pre-wrap`, no scroll box, no type — the transcript rendered as
one mashed wall of text. Versioned asset URLs (`?v=2`) fix it.
**If you change an element type or a selector again, bump the version.**

## 4. Open questions and unverified claims

Treat everything here as unfinished. Do not report any of it as done.

1. **Turn-1 pacing — the owner's authorial call, still unanswered.**
   `data/scenarios/war_game_2025/episodes/turn_001.yaml` opens with the National
   Security Advisor delivering five developments at once (murdered F-35 pilots,
   Severomorsk accusation, 15-submarine deployment, cyber spike, departing
   diplomats). The owner repeatedly reads this as "too many injects". It is
   *not* an engine bug: it is authored text, present since the repo's first
   commit (`4dc1591`, 25 Feb 2026), transcribed from podcast episode 1.
   Options put to the owner and never resolved: (a) leave it; (b) re-pace so
   turn 1 carries only the fleet detection and the rest arrives through play;
   (c) keep all five facts but dramatise them as five voices in the room, which
   is how every other turn is written and closer to how the podcast plays.
   **Do not change it without the owner's explicit say-so and a diff shown first.**

2. **Campaign structure is three designs layered on each other.** The podcast
   runs a handful of enormous beats, each fully deliberated. The original
   AI Studio prototype (vendored at `@filing/GoogleAIStudioTest/` in commit
   `4dc1591`) had *no script at all* — one instruction to Gemini and everything
   emerged. The Python port invented a ladder of small scripted beats for turns
   2–5, marked "extrapolated from wargame patterns" in
   `data/scenarios/war_game_2025/episodes/README.md`. That ladder matches
   neither source. Worth raising, not worth fixing unasked.

3. **There is no game clock.** Episode files carry timestamps ("19:00, 2 hours
   after COBRA") almost entirely in YAML *comments* the player never sees.
   `game_time` is set once at start and never advances; the CLI front ends
   overwrite it with the literal string `"Turn {N}"`; the prompt builders
   dropped it as stale. So the passage of time is whatever the narrator model
   invents. Either give the world a real clock or delete the vestigial
   timestamps — currently it half-claims a timeline it does not keep.

4. **UNVERIFIED — the generic advisor titles.** When calls fail, replies appear
   under MILITARY COMMANDER / INTELLIGENCE COORDINATOR / DOMESTIC SECURITY /
   DIPLOMATIC LEAD / LEGAL ADVISOR instead of the real cabinet (Chief of the
   Defence Staff, National Security Advisor, Home Secretary, Foreign Secretary,
   Attorney General). I told the owner those generic names *are* the offline
   stand-in cast. That was inferred from contrast — my live probes printed the
   real titles, their failing session printed generic ones — **not confirmed in
   the code.** Check `engine/game_manager.py: _PERSONA_ROLE_TITLES` and the mock
   provider's roster before repeating the claim. If generic titles can also
   appear on live calls (e.g. in emergent mode), that is a real bug: the advisor
   picker offers UK titles the transcript never uses, so the player cannot tell
   who is who and reasonably asks "who is the legal advisor?" and "why can't I
   talk to my intelligence officer?" (Answer given: there is no separate
   intelligence officer; intelligence sits with the NSA.)

5. **Unexamined:** whether the cabinet over-reacts to throwaway remarks. The
   owner made a joke in a private meeting and the room treated it as a public
   statement being amplified by Russian state media. That episode was produced
   by the *mock* cast, so it proves nothing — but it is worth reproducing on a
   working model before dismissing.

## 5. Rules of engagement with the owner

These were all stated by the owner, most of them more than once. Violating them
is what made this session expensive and unpleasant.

- **Speak plainly.** No jargon, no invented terminology, no hedging padding.
  If work is outstanding, say so in a sentence.
- **Never put mechanics-speak in a player surface.** No "metrics withheld", no
  parse-health lines, no editorial asides in prose or UI. This has happened
  repeatedly and the owner is rightly sick of it.
- **Never change authored content without diffing the original first and showing
  the diff before merge.** An audit once called a deliberate silence in the
  opening scene a "gap"; the rewrite stuffed two events into the intro and broke
  the owner's cold open. `assets/placeholders/intro_stage.md` was restored
  verbatim from `4dc1591`. Do not repeat this.
- **No constant may bind in normal play.** Length and size discipline belong in
  prompts and turn-boundary structure. Constants exist only as never-fire
  tripwires (see `MAX_ADVISOR_TRANSCRIPT_CHARS` in `llm/context_builder.py`,
  which records a miss rather than cutting content). The event ledger being
  unbounded is by design, not a gap.
- **Do only what was asked.** "The viewer's page reads nicer" is a request to
  restyle, not a licence to redesign the campaign. Conversely, when the owner
  did ask for the whole page restyled, restyling one pane was not enough.
  Read the ask literally, then check.
- **Money is real** — the API key, and agent/token spend too. Measure twice.
- **Distinguish elimination from replication.** When I could not reproduce the
  owner's failure I said so explicitly and listed what I had ruled out. That was
  right; what was wrong was concluding "it's your phone" while a whole class of
  calls was broken in the browser and I hadn't tested it. **Test the specific
  feature the user is complaining about, not an adjacent one.**

## 6. Verification tooling

- **Call log:** set `WARGAME_CALL_LOG=/path.jsonl` and every LLM call is recorded
  (turn, family, tier, provider, model, prompt, reply, finish_reason, latency,
  fallbacks). `dev-scripts/analyse_call_log.py` turns it into a PASS/FAIL verdict.
- **Campaign harness:** `dev-scripts/play_campaign.py` — full campaigns headless,
  state dumps, save/load probes, `--replay-check`.
- **Live browser probe** (built this session, in a scratch dir that will not
  survive — recreate it): Playwright + Chromium at `/opt/pw-browsers/chromium`,
  driving `docs/index.html` served locally, with the key pasted into the own-key
  field. In a sandbox whose egress blocks browser→OpenRouter, run a tiny local
  relay that forwards `/api/v1/chat/completions` upstream via Python `urllib`,
  and put its URL in the page's ENDPOINT field. This is the only way to catch
  browser-only failures like the threadless batch bug — **unit tests and CLI runs
  will not find them.**
- Vendor Pyodide locally with `python3 dev-scripts/fetch_pyodide.py` if the CDN
  is unreachable; `worker.js` prefers the local copy automatically.
